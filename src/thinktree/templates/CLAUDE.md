# 思考 Tree — 给 AI 的工作约定

这个文件夹用一棵"思考 Tree"记录项目的**思考过程**：每个问题从哪个问题分出来、为什么分出来、想完了没有。
主文件是同一文件夹里的 `Tree.md`（以下简称 tree），用 [thinktree](https://github.com/Jiangnan0522/thinktree) 渲染成可交互的思维导图。

> 用法：Claude Code 会自动读这个文件；Codex / Cursor 把它改名为 `AGENTS.md`；
> ChatGPT / 网页版 Claude 把这份说明和 `Tree.md` 的内容一起贴过去（`thinktree prompt` 可以再输出一份）。

## tree 是干什么的

笔记虽然都有，但缺"前因后果"，过几天就忘了当初为什么想这个点、想完了没有。
tree 的作用：随时能快速走一遍 **how we got here / why we got here**；某条路不通时能回溯到原来的节点，换一条路。

## 格式

用户要亲手写，所以语法尽量简单。**一条规则：复选框 = 节点，普通列表行 = 这个节点的说明。**

```markdown
---
cssclasses: thinktree
thinktree: true
---
# 标题

## 主枝标题（09-20 ~ 10-02）
- [x] 问题本身？ => 一句话结论
	- why: 为什么会 branch 到这个问题（可以多句）
		- 补充：被什么触发、和父节点 / 其他节点 [2c2] 什么关系
	- => 详细结论 / 发现
	- ⚠️ 前提或坑 · 📄 [[相关笔记]] §章节
	- [ ] 接着想的子问题？
		- why: ……
	- [-] 被否决的方向 => 为什么不行
	- [x] 实验：v1 对照实验 => A 比 B 好 2 分
```

- **状态**：`[ ]` 进行中 · `[x]` 已定 · `[-]` 否决 · `[>]` 搁置。否决的也**留在树上**，写清为什么，以免以后绕回去。
- **结论**：写在 `=>` 后面。说明行里也可以用 `=>` 开头表示结论，显示时自动变成 →。
- **why 最重要**：说明行以 `why:` 开头，下面缩进的行都算 why 的一部分。查看器把它放进"为什么想这个"卡片和 How we got here。**每个节点都尽量写 why。**
- **标记**：结论之前出现 `⭐` = 重要节点，`🚩` = 待办，一般写成 `- [ ] ⭐ 问题`。
- **节点类型（新节点都要写）**：标题开头写 `实验：` 或 `思考：`，例如 `- [x] 实验：v1 对照 => A 比 B 好`。
  - 实验 = 记录实际跑过 / 要跑的实验、版本迭代、评测，核心是"做了什么、结果是什么"。
  - 思考 = 问题、设计决策、动机、论证、方法论，以及**从实验里归纳出的发现**（即使挂在实验节点下面）。
  - 不按父节点继承，每个节点单独判断；拿不准时问用户。查看器可以按类型只看实验或只看思考。
- **编号自动生成**，按位置 `2 → 2a → 2a1 → 2a1a`，**不要手写**。引用别的节点写 `[编号]`（如 `↔ [2c3]`）；
  插入节点后后面的编号会变，引用可能失效，`thinktree check Tree.md` 会报出来，到时更新引用即可。
- 标题末尾的括号（如 `(10-02)`、`（另一条线）`）和 `↔ [编号]` 会显示成小标签。
- 第一行 `- 📖 …` 下面的内容是图例，不是节点。
- **节点 = 一个问题或决策**，粒度要粗；长论证放到本文件夹的子文件夹笔记里，tree 里只留结论 + 📄 链接。
- **节点名要让没接触过项目的人也能看懂**：先用大白话说这个问题是什么，术语放在括号里补充；结论同样。
- **不是严格的树，更接近 DAG**：一个问题只挂在一个父节点下，其他地方用 `↔ [编号]` 交叉引用，不复制节点。
- 空的 `- [ ] ` 行是用户在查看器里点"＋"插入的占位节点（显示为"（未命名）"），是用户正准备写的位置，不要删掉。
- 缩进用 Tab（和文件里已有的保持一致）。

## 链接规则

- 用 `[[文件名]]` 的形式链接 vault 里的笔记。vault 里有重名文件时用完整路径加别名，例如 `[[文件夹/笔记|笔记]]`。
- 新加的 `[[链接]]` 要确认 vault 里有且只有一个同名文件（`thinktree check Tree.md` 会检查）。

## 日常更新流程（AI 的工作方式）

用户会随手丢一段"今天想了什么 / 定了什么"。处理方式：

1. 先读 tree，找到这个想法的**父节点**。找不到合适的父节点时，先问用户，或者在最相关的主枝下新开一个节点，并说明理由。
2. 新问题 → 在父节点下加一个缩进的复选框，下面写 `why:`。已有问题有了结论 → 改复选框状态，结论写在标题的 `=>` 后，细节写成说明行。
3. 论证较长时，在本文件夹的子文件夹里新建或更新 .md，tree 只留一句结论加 📄 链接。
4. 和其他枝有关系 → 加 `↔ [编号]`。
5. 改动较大时先说要在哪个节点下加什么（状态、一句话结论、why），用户同意后再改。
6. 改完告诉用户：改了哪些节点（编号 + 状态变化），以及哪些状态是你的判断、需要用户确认。

还要注意：

- 遵守原笔记的语言（tree 是中文就写中文，术语可以保留英文）。
- 发现节点之间**前后不一致**（例如某个已定的结论和后来的做法对不上）时，主动指出。
